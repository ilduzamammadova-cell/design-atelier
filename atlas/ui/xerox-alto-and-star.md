# Xerox Alto & Star

**Essence:** The office translated onto a white, paper-proportioned screen, documents, folders and printers as pictures you point at, governed by a few universal verbs.

## Genes

| Gene | The idea | In UI / product terms |
|---|---|---|
| G1 · Universal verbs | The Star reduced commands to a small generic set (Move, Copy, Delete, Show Properties, Again, Undo) that worked identically on text, graphics, files and devices. | Ship 5 to 6 verbs that apply to every object type, on dedicated keys and one toolbar. Forbid object-specific synonyms ("Duplicate", "Clone", "Make copy" → always **Copy**). |
| G2 · Property sheets | Every object's attributes lived in one sheet where all choices were visible at once, current value highlighted. | One inspector pattern for all objects. Options ≤6 are shown as visible segmented choices with the current one inverted, never hidden in a dropdown. |
| G3 · Objects as nouns on a desktop | Documents, folders, in/out baskets and printers were icons; you acted by moving one onto another (a document dropped on a printer prints). | Model the domain as draggable noun-tiles with text labels. Let drop targets be actions (drag invoice onto "Send" tile). The workspace is a surface the user arranges. |
| G4 · Paper-proportioned, true-size page | The Alto's bitmapped display was portrait (606×808) so a page fitted whole; text appeared at real sizes, black ink on white (WYSIWYG, via Bravo on Alto). | Default canvas is white paper with black ink at ~1:1.3 portrait, shown at true scale. Chrome is thin black rules; no background tints behind content. |
| G5 · Point, don't recall | One of the Star team's eight published principles: seeing and pointing beats remembering and typing (others: modelessness, simplicity, user tailorability). | Every action reachable by pointing at something visible; keyboard shortcuts exist only as labelled accelerators displayed next to the visible control. |
| G6 · Tested iconography | Star icons were monochrome, carefully drawn pictograms with labels, refined through user testing. | Icons are 1-bit or single-colour, always paired with a noun label, each with a unique silhouette; run a 5-second recognition test before shipping any new one. |

## Visual facts

- **Color:** pure black on white; a stippled mid-grey desktop field; no hue at all.
- **Type:** Xerox's own proportional bitmap families rendered at true point sizes. Free: **IBM Plex Sans** for chrome, **Source Serif 4** for document text.
- **Form:** document and folder icons drawn by Norm Cox; rectangles with hairline borders, overlapping windows (from Smalltalk), small square icon tiles, black inverted title strips.
- **Composition:** desktop of icons arranged freely; documents open as windows tiling or overlapping; a strict separation of chrome (thin) from content (paper).

## Attitude

PARC believed computers should serve office workers and children rather than programmers. The Star team (including David Canfield Smith, who had named on-screen pictures "icons" in his 1975 Pygmalion thesis) wrote the user's conceptual model first and the software second, and treated consistency as a moral obligation: once a rule was learned it had to hold everywhere. Alan Kay's group, meanwhile, saw the screen as a new creative medium (Smalltalk, the Dynabook idea). Take the discipline of *one model, applied everywhere*, not the beige office.

## Blends

- **Amplifies:** `classic-macintosh`, `swiss-international`, `ulm-school`, rule-first systems that value consistency over flourish.
- **Productive tension with:** `memphis`, whimsical, patterned objects living inside a rigorously consistent verb system: playful surface, unbreakable logic.
- **Clashes with:** `flash-era-web`, bespoke, toy-like controls per screen destroy the universal-verb contract that makes this language work.
